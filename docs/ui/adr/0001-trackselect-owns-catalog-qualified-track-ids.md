# TrackSelect owns catalog-qualified track IDs

TrackSelect owns only store tracks whose IDs exactly match entries in its supplied catalogs, using the public `${catalogId}::${trackId}` format. Initialization and successful Submit may replace or remove those catalog-owned tracks, while every nonmatching track remains host-owned and must be preserved in its existing order; draft actions such as Reset only choose catalog-owned IDs for a later Submit. Ownership is determined by ID alone rather than runtime metadata or track configuration so reconciliation remains deterministic and catalog selections stay portable. Fixed or otherwise unmanaged tracks can use any ID that does not exactly match a supplied catalog entry; an exact collision is treated as catalog-owned even if the host created that track outside TrackSelect.
