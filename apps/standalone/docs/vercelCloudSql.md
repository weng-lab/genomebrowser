# Connect Vercel previews to Cloud SQL

The app client, `genomebrowser-dev` database, and initial migrations are ready. Finish the Google and Vercel configuration below. Local development keeps using your existing proxy and `DATABASE_URL`.

## 1. Get your Vercel team slug

Open the `genomebrowser` project in Vercel. Its dashboard URL looks like `https://vercel.com/TEAM_SLUG/genomebrowser`. Copy `TEAM_SLUG`, using the URL value rather than the team's display name.

Under **Settings → Security → Secure backend access with OIDC federation**, select **Team** and save. [Vercel OIDC settings](https://vercel.com/docs/oidc#issuer-mode)

## 2. Create the Google service account

Run these commands in your terminal while signed into Google Cloud:

```bash
gcloud services enable sqladmin.googleapis.com iamcredentials.googleapis.com sts.googleapis.com \
  --project=devenv-215523

gcloud iam service-accounts create genomebrowser-preview \
  --display-name="Genomebrowser Vercel previews" \
  --project=devenv-215523

gcloud projects add-iam-policy-binding devenv-215523 \
  --member="serviceAccount:genomebrowser-preview@devenv-215523.iam.gserviceaccount.com" \
  --role="roles/cloudsql.client" \
  --condition=None
```

This creates the Google identity used by Vercel. Your existing PostgreSQL username and password are still used to log into the database.

## 3. Create the connection between Vercel and Google

In Google Cloud Console, select **devenv-215523**, then open **IAM & Admin → Workload Identity Federation → Create pool**.

Fill in these values. Replace `TEAM_SLUG` with the value from step 1.

| Field                | Value                               |
| -------------------- | ----------------------------------- |
| Pool name and ID     | `genomebrowser-vercel`              |
| Provider type        | OpenID Connect / OIDC               |
| Provider name and ID | `vercel`                            |
| Issuer URL           | `https://oidc.vercel.com/TEAM_SLUG` |
| JWK file             | Leave empty                         |
| Audience             | **Default audience**                |
| Google attribute     | `google.subject`                    |
| OIDC attribute value | `assertion.sub`                     |

Keep the pool and provider enabled, then save. These settings match the audience generated by the app client. [Vercel's Google setup guide](https://vercel.com/docs/oidc/gcp)

Next, replace `TEAM_SLUG` in this command and run it. It lets only the `genomebrowser` project's preview deployments use the service account:

```bash
gcloud iam service-accounts add-iam-policy-binding \
  genomebrowser-preview@devenv-215523.iam.gserviceaccount.com \
  --project=devenv-215523 \
  --role="roles/iam.workloadIdentityUser" \
  --member="principal://iam.googleapis.com/projects/705860088578/locations/global/workloadIdentityPools/genomebrowser-vercel/subject/owner:TEAM_SLUG:project:genomebrowser:environment:preview"
```

## 4. Add the Vercel environment variables

Open **genomebrowser → Settings → Environment Variables**. Add each variable below with **Preview** selected. Replace the username and password placeholders with the PostgreSQL credentials that already work locally.

```dotenv
INSTANCE_CONNECTION_NAME=devenv-215523:us-east1:genesmetadata-instance
DB_NAME=genomebrowser-dev
DB_USER=YOUR_DATABASE_USERNAME
DB_PASSWORD=YOUR_ORIGINAL_DATABASE_PASSWORD
GCP_PROJECT_NUMBER=705860088578
GCP_SERVICE_ACCOUNT_EMAIL=genomebrowser-preview@devenv-215523.iam.gserviceaccount.com
GCP_WORKLOAD_IDENTITY_POOL_ID=genomebrowser-vercel
GCP_WORKLOAD_IDENTITY_POOL_PROVIDER_ID=vercel
```

Enter the original password, not the URL-encoded version. For example, use `@` rather than `%40`.

Also make sure `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` are set for Preview, using the same Clerk environment as local development.

Leave the local `DATABASE_URL` on your computer. Vercel supplies its OIDC token automatically; there is no Google key file or token to copy. The client computes the audience, so no `GCP_AUDIENCE` variable is needed.

## 5. Deploy and check

1. Push the client changes to a non-production branch and deploy that branch as a Vercel preview. If it already has a deployment, redeploy after saving the variables.
2. Open the preview and sign in.
3. Create a session, change its region, then reload and reopen it.
4. Confirm the changes were saved. You can also open that session locally with the same account because both apps use `genomebrowser-dev`.

Use a **Preview** deployment for these steps. Vercel's **Development** environment is for local development; a deployment marked **Production** will not match the preview-only Google permission above.

If saving fails, open the deployment's runtime logs. Check the exact team slug and preview permission from step 3, the eight variables from step 4, and the PostgreSQL password. A successful build alone does not verify database access.

## Connection notes

The Cloud SQL instance must have public IP enabled. The connector encrypts the connection without adding Vercel IP addresses to authorized networks. Each running function process can open up to five database connections.

Provide Clerk keys at build time and runtime. Next.js embeds the publishable key in the client bundle, so changing Clerk applications requires rebuilding. Configure the intended domains and sign-in methods in Clerk. Shared API Console accounts do not establish cross-domain single sign-on without Clerk's multi-domain configuration.

Builds do not run database migrations. Apply reviewed migrations through the local proxy with an appropriately privileged login. Preview deployments sharing `genomebrowser-dev` also share records and schema changes.

For the local proxy, migrations, and tests, follow [local development](localDevelopment.md). Return to [standalone docs](README.md).
